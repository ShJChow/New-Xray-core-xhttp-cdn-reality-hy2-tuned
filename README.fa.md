# xray-xhttp

**زبان‌ها:** [简体中文](./README.md) · [English](./README.en.md) · **فارسی**

> **آزمایش‌شده و بهینه‌سازی‌شده روی Oracle ARM (۴ هسته / ۲۴ گیگابایت رم) و اوبونتو 26.04.** تنظیم‌شده برای حفظ پایداری اتصال و جلوگیری از مسدودسازی اکانت‌های هوش مصنوعی.

راهکار همه‌کاره با در دسترس بودن بالا برای استقرار **XHTTP + CDN + Reality + Hysteria2** بر پایهٔ Xray-core. به‌صورت پیش‌فرض مجهز به **مبهم‌سازی ترافیک xpadding / مبهم‌سازی Salamander در Hysteria2 / ۸ نود اصلی**، همراه با اعمال خودکار **تنظیمات شبکه و هسته (BBR+fq، بافرهای ۶۴ مگابایتی، ۱۰۴۸۵۷۶ دیسکریپتور فایل، ایمن‌سازی امنیتی)** هنگام نصب، و ابزار مدیریتی مقیم **`xh`**.

پشتیبانی از کلاینت‌های V2rayN، Clash Verge Rev، Mihomo Party، Sing-box، Shadowrocket، Loon، Surge، onexray و غیره.

## ۱. پیش‌نیازها

پیش از اجرای اسکریپت، **۲ زیردامنه متصل به IP سرور خود** آماده کنید (پیشنهاد: Cloudflare):
- **دامنهٔ ۱ (مستقیم / Reality)**: مانند `reality.example.com`
- **دامنهٔ ۲ (دامنهٔ CDN)**: مانند `cdn.example.com`

---

### ۱.۱ تنظیم رکوردهای DNS

در بخش DNS کلودفلر، دو رکورد `A` به سمت IP عمومی VPS خود ایجاد کنید:

| نوع رکورد | نام | IP مقصد | وضعیت پروکسی | کاربرد |
| :--- | :--- | :--- | :--- | :--- |
| **رکورد A** | `reality.example.com` | `IP سرور شما` | **فقط DNS (ابر خاکستری)** | صدور گواهی و اتصال مستقیم Reality / Hy2 |
| **رکورد A** | `cdn.example.com` | `IP سرور شما` | **پروکسی‌شده (ابر نارنجی)** | نود CDN برای پنهان‌سازی IP اصلی |

---

### ۱.۲ تنظیمات داشبورد Cloudflare

گزینه‌های زیر را در داشبورد کلودفلر فعال کنید:

1. **SSL/TLS** ➡️ **Overview**: حالت رمزنگاری **Full (strict)**؛
2. **SSL/TLS** ➡️ **Edge Certificates**: حداقل نسخهٔ TLS: **TLS 1.2**؛
3. **Network**:
   - فعال‌سازی **gRPC**
   - فعال‌سازی **WebSockets**
   - فعال‌سازی **HTTP/3 (with QUIC)**
   - فعال‌سازی **0-RTT Connection Resumption**
4. **Rules** ➡️ **Cache Rules (اختیاری)**:
   - تنظیم **Bypass Cache** برای مسیر XHTTP جهت جلوگیری از بافرینگ جریانی.

---

### ۱.۳ صدور گواهی SSL

اسکریپت نصب به‌صورت خودکار گواهی را با `acme.sh` دریافت می‌کند. برای صدور دستی پیش از نصب:

```bash
# آزادسازی پورت 80 در صورت اشغال
systemctl stop nginx xray 2>/dev/null || true

# اجرای اسکریپت acme-yg
bash <(curl -Ls https://raw.githubusercontent.com/yonggekkk/acme-yg/main/acme.sh)

# کپی گواهی به مسیر استاندارد
mkdir -p /etc/ssl/private
cp -f /root/ygkkkca/reality.example.com/fullchain.cer /etc/ssl/private/fullchain.cer
cp -f /root/ygkkkca/reality.example.com/private.key /etc/ssl/private/private.key
chmod 600 /etc/ssl/private/*.key
```

## ۲. استقرار تک‌دستوری

### ۲.۱ استقرار تعاملی

ورود به سرور با دسترسی روت:

```bash
sudo -i

```

---

### ۲.۲ استقرار خودکار با متغیرهای محیطی

اجرای تک‌خطی بدون نیاز به پاسخ‌دهی تعاملی:

```bash
sudo bash <(curl -fsSL https://github.com/ShJChow/New-Xray-core-xhttp-cdn-reality-hy2-tuned/releases/latest/download/install.sh) AUTO=1 REALITY_DOMAIN="reality.example.com" CDN_DOMAIN="cdn.example.com" NODE_TAG="vps"
```

#### متغیرهای محیطی کلیدی

| متغیر | مقدار پیش‌فرض | توضیح |
| :--- | :---: | :--- |
| `AUTO` | `0` | مقدار `1` برای نصب کاملاً خودکار و بدون تعامل. |
| `REALITY_DOMAIN` | — | **دامنهٔ مستقیم / Reality** (ابر خاکستری کلودفلر). |
| `CDN_DOMAIN` | — | **دامنهٔ CDN** (ابر نارنجی کلودفلر). |
| `FEATURE_AUTO_TUNING` | `true` | فعال‌سازی BBR+fq، بافرهای ۶۴ مگابایتی و بهینه‌سازی سیستم. |
| `FEATURE_XPADDING` | `true` | فعال‌سازی پرکردن ترافیک برای رفع الگوهای طول پکت. |
| `FEATURE_BRUTAL` | `true` | کنترل ازدحام TCP Brutal (۹۵٪ سرعت شبکه). |
| `REALITY_MIN_CLIENT_VER` | `1.8.0` | سازگاری نسخه کلاینت (پیش‌فرض `1.8.0` برای Mihomo/Clash/sing-box). |

## ۳. دستور مدیریتی `xh`

```bash
xh                     # باز کردن منوی تعاملی مدیریت
xh status              # وضعیت سرویس‌ها، پورت‌ها و پارامترهای بهینه‌سازی
xh info                # نمایش پارامترهای نودها و لینک‌های اشتراک
xh sub                 # نمایش لینک‌های اشتراک و QR کد ترمینال
xh resub               # بازتولید اشتراک‌های کلاینت
xh minversion [on|off] # مدیریت حداقل نسخهٔ مجاز کلاینت در Reality
xh ech [show|on|off]   # کلید Cloudflare CDN ECH و همگام‌سازی اشتراک
xh ecn [show|on|off]   # وضعیت و تنظیم TCP ECN
xh cdnh2 [show|on|off] # فعال‌سازی نود پشتیبان CDN TCP (h2)
xh brutal              # وضعیت و تنظیم پهنای باند TCP Brutal
xh tuning [win|mac|sb] # نمایش دستورات بهینه‌سازی کلاینت
xh conflict            # بررسی و رفع خودکار تداخل پارامترهای sysctl
xh log [xray|nginx]    # مشاهدهٔ زندهٔ لاگ‌ها
xh update [--auto]     # به‌روزرسانی هستهٔ Xray با قابلیت بازگشت خودکار
xh restart             # راه‌اندازی مجدد سرویس‌های xray و nginx
```

## ۴. راهنمای بهینه‌سازی کلاینت برای شبکه‌های گیگابیتی

برای شبکه‌های بین‌المللی گیگابیتی و پینگ‌های بالا، می‌توانید سیستم کلاینت را بهینه‌سازی کنید:

- **ویندوز ۱۰ / ۱۱ (PowerShell در حالت ادمین)**:
  ```powershell
  irm https://reality.example.com/sub/<Token>/win.ps1 | iex  # یا اجرای xh tuning win روی سرور
  ```
- **مک‌او‌اس (ترمینال - افزایش بافر به ۳۲ مگابایت)**:
  ```bash
  sudo sysctl -w kern.ipc.maxsockbuf=33554432 net.inet.tcp.recvspace=4194304 net.inet.tcp.autorcvbuf=1 net.inet.tcp.autorcvbufmax=33554432 net.inet.tcp.fastopen=3
  ```
- **لینوکس**:
  ```bash
  sudo sysctl -w net.core.rmem_max=67108864 net.ipv4.tcp_rmem="4096 262144 67108864" net.ipv4.tcp_fastopen=3
  ```

## ۵. توپولوژی نودها و معماری دوگانه

```mermaid
flowchart TD
    Client[دستگاه کاربر] --> Router{مسیریابی / تست خودکار}
    
    subgraph سناریوی B: حداکثر کارایی (استفادهٔ روزمره ۹۰٪)
        Router -->|اتصال مستقیم کم‌تأخیر| Reality[VLESS-Reality-Vision<br>TCP 443 Splice بدون کپی]
        Router -->|مقاومت در برابر افت پکت| Hy2[Hysteria 2<br>UDP 443 موتور Brutal]
        Reality --> VPS[IP اصلی سرور]
        Hy2 --> VPS
    end
    
    subgraph سناریوی A: بقا و ضد فیلترینگ
        Router -->|ضد مسدودسازی / پنهان‌سازی| XHTTP[VLESS-XHTTP<br>TCP/UDP 443 مالتی‌پلکس xmux]
        XHTTP --> CF[لبه‌های شبکه Cloudflare]
        CF -->|جریان پایدار بازگشت به مبدأ| Nginx[Nginx grpc_pass<br>انتقال بدون بافر]
        Nginx --> XrayInbound[ورودی 8001 داخلی Xray]
    end
```

| # | نام نود (v4.9.38) | پروتکل انتقال | توپولوژی مسیریابی | ویژگی‌های کلیدی |
| :--- | :--- | :--- | :--- | :--- |
| **۱** | `VLESS-XHTTP-CDN-H2` | XHTTP (h2) + vlessenc | از مسیر CDN TCP 443 | **مسیر پایدار TCP**، راه خروج اضطراری هنگام مسدودسازی UDP |
| **۲** | `VLESS-XHTTP-CDN-H3` | XHTTP (QUIC) + vlessenc | از مسیر CDN 443 | **پنهان‌سازی IP اصلی**، عبور از فیلترینگ شدید |
| **۳** | `VLESS-XHTTP-Direct-H3` | XHTTP (QUIC) + vlessenc | مستقیم UDP 8443 | پروتکل QUIC مستقیم، `mode=stream-up` |
| **۴** | `Hysteria2-H3-Direct` | Hysteria 2 | مستقیم UDP 443 | ساختار استاندارد HTTP/3، بالاترین سرعت دانلود |
| **۵** | `VLESS-Reality-Vision-Direct` | VLESS-Reality | مستقیم TCP 443 | **فناوری xtls-rprx-vision**، بالاترین سرعت تک‌جریان |
| **۶** | `VLESS-Reality-XHTTP-Direct` | XHTTP-Reality + vlessenc | مستقیم TCP 443 | استتار Reality با مبهم‌سازی پرکردن داده |
| **۷** | `VLESS-Reality-Up-CDN-Down` | تفکیک مسیر + vlessenc | ارسال Reality مستقیم / دریافت CDN (h2) | اتصال مستقیم فوق‌سریع Reality + دریافت ضد فیلتر از CDN |

> غیرفعال به صورت پیش‌فرض، قابل فعال‌سازی: `VLESS-CDN-Up-Reality-Down` (`FEATURE_CDN_UP_REALITY_DOWN`), `VLESS-XHTTP-Direct-H2` (`FEATURE_H2_DIRECT`), `Hysteria2-Obfs-Direct` (`FEATURE_HY2_OBFS`).

## ۶. عیب‌یابی و پرسش‌های متداول

| مشکل | علت اصلی | راه‌حل سریع |
| :--- | :--- | :--- |
| **عدم اتصال نود Reality** | اختلاف ساعت سیستم کلاینت > ۳۰ ثانیه | فعال‌سازی «تنظیم خودکار ساعت شبکه» در سیستم‌عامل |
| **خطای تفکیک مسیر در Mihomo** | کپی ناخواستهٔ تنظیمات والد در کلاینت | درج صریح `reality-opts: { public-key: "" }` در بخش `download-settings` |
| **تایم‌اوت UDP یا Hysteria 2** | مسدود بودن در فایروال ارائه‌دهنده ابری | باز کردن پورت‌های UDP 443 / 8443 / 8446 و TCP 443 / 8445 در فایروال |
| **تداخل در تنظیمات sysctl** | اسکریپت‌های متفرقه در `/etc/sysctl.d/` | اجرای دستور `xh conflict` برای شناسایی و رفع خودکار |

## ۷. تاریخچهٔ نسخه‌ها و روند بهینه‌سازی (v4.8 - v4.9.38)

خلاصهٔ دستاوردهای فنی حاصل از ده‌ها مرحله آزمایش عملی در شرایط افت پکت و تأخیر بین‌المللی (160ms+ / 1%):

| حوزهٔ فنی | نسخه‌ها | استراتژی فنی و نتایج حاصله |
| :--- | :--- | :--- |
| **تثبیت نسخهٔ رسمی پایدار** | v4.9.8–v4.9.18 | قفل کامل روی نسخهٔ رسمی `releases/latest` (نسخهٔ v26.3.27) و پرهیز از کلیدهای ناپایدار پسا-کوانتومی (MLKEM768)؛ پاک‌سازی سینتکس اشتراک کلاینت‌ها. |
| **توپولوژی تفکیک مسیر** | v4.9.19–v4.9.29 | توسعهٔ Reality-Up-CDN-Down و CDN-Up-Reality-Down؛ رفع باگ ارث‌بری در Mihomo؛ رمزنگاری vlessenc در پورت 8001 جهت جلوگیری از شنود CDN. |
| **بهینه‌سازی شبکه و جریان** | v4.8.x–v4.9.30 | همگام‌سازی با BBRv3 و TCP Brutal (قفل روی ۳۸۰۰ مگابیت)؛ تثبیت بافر با کارایی اثبات‌شدهٔ **۶۴ مگابایت**؛ تعادل وقفه نرم‌افزاری RPS/RFS؛ پشتیبانی از TLS 1.3 و ECH/ECN. |
| **امنیت جامع و مقابله با سیل پکت** | v4.9.17–v4.9.33 | غیرفعال‌سازی پرش پورت پیش‌فرض و همگرایی روی تک‌پورت Hy2 (پورت UDP 443)؛ سیستم محدودکنندهٔ hashlimit در Netfilter؛ جلوگیری از دامپ حافظه (`fs.suid_dumpable=0`). |
| **بازبینی کندی نودها** | v4.9.34 | آزمون مجدد همهٔ نودها (netns، 160ms/1% افت، 300↓/50↑): افت سمت سرور وجود ندارد؛ brutal و bbr هم‌پوشان → brutal حفظ شد؛ مسیر ارسال `CDN-Up-Reality-Down` به h3 بازگشت (10 → 34 Mbps)؛ رفع اشکال `tools/xray_rtt_bench.py` برای نودهای CDN. |
| **ساده‌سازی پیش‌فرض توپولوژی** | v4.9.35 | حذف پیش‌فرض `VLESS-XHTTP-CDN-H2` و `VLESS-Reality-Up-CDN-Down` برای تمرکز بر ۶ نود پرسرعت؛ امکان فعال‌سازی بر حسب نیاز. |
| **بهینه‌سازی تفکیک مسیر** | v4.9.36 | جایگزینی نود تفکیک مسیر با `VLESS-Reality-Up-CDN-Down` (ارسال مستقیم Reality + دریافت H2 از CDN) به عنوان یکی از ۶ رکن اصلی؛ رفع باگ پارامتر دانلود در کلاینت بدون xpadding. |
| **تثبیت تزریق احراز هویت** | v4.9.37 | افزودن تابع `rawurlencode` و مکانیزم فال‌بک `HY2_PASSWORD` در تولید پیکربندی کلاینت جهت رفع مشکل حذف یا خطای اتصال نود Hysteria 2 در اشتراک‌ها. |
| **بازیابی پیش‌فرض CDN-H2** | v4.9.38 | فعال‌سازی مجدد نود `VLESS-XHTTP-CDN-H2` به صورت پیش‌فرض (مجموعاً ۷ نود اصلی)، جهت تضمین دسترسی پایدار از طریق TCP هنگام اختلال یا افت سرعت در پروتکل UDP. |
