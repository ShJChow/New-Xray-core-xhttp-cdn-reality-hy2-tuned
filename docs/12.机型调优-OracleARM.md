# XHTTP + CDN 搭建指南 (十二)：机型自适应调优与 Oracle ARM 专项

安装脚本会自动探测 CPU 核数、物理内存与 CPU 架构，按内存分三档设定内核参数与 Xray `policy.bufferSize`。本文说明分档依据，以及 Oracle Cloud Ampere A1（ARM64）上两个必须知道的坑。

查看本机被判为哪一档：

```bash
xh status        # 输出「机型 / 调优档位」与「Xray policy.bufferSize」
nproc; free -m; uname -m
```

---

## 1. 三档参数表

| 档位 | 触发条件 | `rmem_max`/`wmem_max` | `tcp_rmem`/`tcp_wmem` 上限 | `netdev_max_backlog` | `nf_conntrack_max` | Xray `bufferSize` |
|---|---|---|---|---|---|---|
| large | 内存 ≥ 16 GB | 64 MB | 32 MB | 65536 | 1048576 | 512 KB |
| medium | 内存 ≥ 4 GB | 32 MB | 16 MB | 32768 | 262144 | 256 KB |
| small | 内存 < 4 GB | 16 MB | 8 MB | 16384 | 不调整 | 64 KB |

`net.ipv4.tcp_mem` 三个阈值按物理内存页数的 6% / 8% / 12% 推算，不再是固定常量——小内存机上写死大值会挤占系统内存。

`nf_conntrack_*` 仅在 `/proc/sys/net/netfilter/nf_conntrack_max` 可读（即模块已加载）时才写入，否则跳过。

Oracle Ampere A1 **4 OCPU / 24 GB** 命中 **large** 档：`tcp_mem` 约 1.4 / 1.9 / 2.9 GB，`bufferSize` 512 KB。

---

## 2. ARM64 的 `policy.bufferSize` 坑（最重要）

Xray 的 `policy.levels.0.bufferSize` 是**每个请求的内部缓存**，单位 KB。它的默认值随平台不同：

| 平台 | 默认 `bufferSize` |
|---|---|
| ARM / MIPS / MIPSLE | **0** |
| **ARM64** / MIPS64 / MIPS64LE | **4 KB** |
| 其它（amd64 等） | 512 KB |

也就是说，**同样的配置跑在 Oracle ARM 机器上，Xray 的内部缓存只有 x86 机器的 1/128**。这是 ARM VPS 上"配置一模一样、速度就是上不去"的常见原因之一。

本项目现在会显式写入该字段：

```json
"policy": {
    "levels": {
        "0": {
            "handshake": 4,
            "connIdle": 300,
            "uplinkOnly": 2,
            "downlinkOnly": 5,
            "bufferSize": 512
        }
    },
    "system": {
        "statsInboundUplink": false,
        "statsInboundDownlink": false,
        "statsOutboundUplink": false,
        "statsOutboundDownlink": false
    }
}
```

超时相关的四项一律沿用 Xray 官方默认值，本项目不擅自改动。

> **说明**：`bufferSize` 默认值差异有官方文档依据，但**具体能带来多少吞吐提升本项目未做实测**。如果想自己对比，改 `/usr/local/etc/xray/config.json` 里的该数值后 `xh restart`，用同一条链路跑两次测速即可。
>
> 也可以用环境变量覆盖（单位是 MB，`XRAY_RAY_BUFFER_SIZE=1` 等价于配置里的 1024）。

## 3. Oracle 特有：443 端口要放行两层

Oracle Cloud 的默认镜像（Ubuntu / Oracle Linux）自带一套 iptables 规则，**`INPUT` 链只放行 22**，其余全部 REJECT。加上 VCN 的安全列表，一共两层。只改一层，表现是"脚本跑完全绿、证书也签下来了，客户端就是连不上"。

**第一层 · VCN 安全列表 / 网络安全组**（Web 控制台）
入站规则加：`0.0.0.0/0` → TCP `443`、UDP `443`、UDP `8443`。

**v4.0.0 起三个端口都要放行**：
- **TCP 443** — Reality（`Vless-reality-vision` / `Vless-xhttp-reality`）
- **UDP 443** — `Vless-xhttp-h3-direct`，由 Xray 自己监听（不经 nginx，也不经 CDN）
- **UDP 8443** — `Hysteria2-obfs`，Xray 原生 hysteria inbound

经 CDN 的 `Vless-xhttp-tls-UDP-cdn` 是例外：HTTP/3 由 Cloudflare 边缘终结、回源仍是 TCP，
它不依赖本机的任何 UDP 放行。所以「只开 TCP 443」时该节点仍可用，另两条 UDP 节点会超时——
**这正是最容易误判为「节点配置错了」的情形**，实际是安全组少放行了两个 UDP 端口。

**第二层 · 实例内 iptables**

```bash
# 查看当前规则，确认是否只有 22 被放行
sudo iptables -L INPUT -n --line-numbers

# 放行 443（TCP/UDP），插到 REJECT 规则之前
sudo iptables -I INPUT 6 -p tcp --dport 443 -j ACCEPT
sudo iptables -I INPUT 6 -p udp --dport 443 -j ACCEPT
# UDP 8443：Hysteria2-obfs 节点（v4.0.0 起为默认节点）
sudo iptables -I INPUT 6 -p udp --dport 8443 -j ACCEPT
# 80 端口：acme.sh standalone 签证书时需要，签完可关
sudo iptables -I INPUT 6 -p tcp --dport 80 -j ACCEPT

# 持久化（Ubuntu）
sudo apt install -y netfilter-persistent iptables-persistent
sudo netfilter-persistent save
```

> 行号 `6` 要按 `iptables -L INPUT --line-numbers` 的实际输出调整——必须**排在 REJECT all 那一条之前**，否则不生效。
>
> Oracle Linux / 启用了 firewalld 的镜像用：
> `sudo firewall-cmd --permanent --add-port=443/tcp --add-port=443/udp --add-port=80/tcp && sudo firewall-cmd --reload`

验证：

```bash
xh status                      # 确认 xray/nginx 在监听 443
curl -sv https://你的CDN域名/ 2>&1 | head -20    # 从外部机器执行
```

## 4. 其它 ARM64 注意事项

- **Xray 二进制**：官方 `install-release.sh` 会自动选 `Xray-linux-arm64-v8a`，无需手动处理。
- **Nginx**：本项目从源码编译，ARM64 上正常，只是 4 核编译约需 1–2 分钟。
- **BBR**：Oracle 的 Ubuntu 22.04/24.04 内核自带 BBR，探测会直接通过；若用了自定义精简内核，脚本会告警并保持系统默认拥塞算法，其余调优照常生效。


---

## 5. 关闭或回滚

```bash
xh tuning show     # 查看本项目写入的内核参数
xh tuning on       # 开启系统层调优（v4.2.0 起安装时已自动执行）
xh tuning off      # 移除全部调优文件
```

**v4.2.0 起安装完成时自动执行调优**，跳过用 `FEATURE_AUTO_TUNING=false`。
Xray 的 `policy.bufferSize` 由安装脚本按内存分档自动注入（v3.0.0 起），无需手动编辑。
